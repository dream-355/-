# 安全与隐私设计

## 认证与会话

- 密码使用 PBKDF2-HMAC-SHA256，310,000 次迭代，每用户独立随机盐，数据库中不存明文或可逆密文。
- 会话令牌为 256 位随机值，数据库仅存 SHA-256 摘要，泄露数据库无法直接复用令牌。
- Cookie 设置 `HttpOnly`、`SameSite=Lax`；生产环境通过 `COOKIE_SECURE=true` 开启 `Secure`，配合 HTTPS 使用。
- 修改账号或密码需要验证当前密码，邮箱重复会被拒绝。

## 暴力破解防护

`/api/auth/login`、`/api/auth/register`、`/api/auth/account` 采用 60 秒滑动窗口限流，默认每分钟 10 次，可通过 `AUTH_RATE_LIMIT_PER_MINUTE` 调整。超限返回 429。

已知限制：限流按客户端 IP 计数，部署在反向代理后需要正确设置 `X-Forwarded-For` 并由代理层再做一层全局限流。

## 数据边界

- 用户档案、对话、体征记录保存在本地 SQLite，不写入 Neo4j 医疗知识图谱。
- 上传图片仅用于当次模型请求，不落库；可在界面与文档中核查。
- 模型 API Key 仅从服务端环境变量读取，前端任何接口都不会返回密钥内容。
- 演示脚本 `scripts/reset_demo.py` 可清空演示账号数据，恢复到已知状态。

## 已知未实现项

- 修改密码后不会强制其它设备下线；如需改密即踢出，需要在更新密码时清理该用户除当前会话外的 session。
- 未实现字段级加密（SQLCipher）、审计日志与数据导出删除自助页面。
- 未接入 CSRF Token；当前依赖 `SameSite=Lax` 与仅接受 JSON 请求体，若未来开放跨站表单提交需要补充。
