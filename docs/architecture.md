# 技术架构与可信设计

## 总体链路

```text
用户问题
  → 医疗实体识别
  → Neo4j 全文检索
  → 一跳关系与证据整理
  → 用户档案 / 会话摘要 / 风险规则上下文
  → DeepSeek 受约束生成
  → 急症兜底校验
  → 回答 + 证据链 + 会话持久化
```

前端不直接持有数据库凭据或模型 Key。FastAPI 作为唯一业务入口，负责鉴权、数据隔离、图谱访问、模型调用和输出兜底。

## 为什么不是普通说明书 RAG

普通 RAG 往往只返回相似文本，难以表达“疾病—症状—检查—治疗”的结构。本项目将问题映射为图谱实体，同时使用 Neo4j 全文检索与本地字符向量召回，再按问题意图沿真实关系收集证据。回答中的 `[E#]` 可直接展开主体、关系和客体。

检索结果按问题意图分为症状、病因、检查、治疗、科室和注意事项，只把对应关系类型送入模型；低相关事实保留为上下文但不会作为主要判断依据。

系统明确区分：

- 图谱命中：某个名称出现在知识库中；
- 相关知识：实体之间存在 Neo4j 关系；
- 风险判断：独立规则命中了可解释的危险模式；
- 医疗诊断：系统不会给出确定诊断。

这种区分避免了把“相关”误导成“因果”。

## 数据模型

### Neo4j

复用现有 38 类实体、141,178 个节点、684,564 条关系。实体名称字段为 `name`，主要关系包括：

- `symptomAndSign`：疾病与症状体征
- `relatedSymptom`：相关症状
- `check` / `auxiliaryExamination`：检查
- `drugTherapy` / `treatmentPrograms`：治疗与用药
- `department`：就诊科室
- `complication` / `cause` / `precautions`：并发症、病因和注意事项

项目仅新增 `medical_entity_search` 全文检索索引，不修改或覆盖原节点与关系。

### SQLite

- `users`：账户
- `sessions`：会话令牌摘要
- `health_profiles`：健康档案
- `health_records`：连续健康指标
- `conversations`：对话标题、摘要和风险等级
- `messages`：消息正文与结构化证据 trace

密码使用 PBKDF2-HMAC-SHA256 加盐哈希；会话使用 256 位随机令牌，并以 SHA-256 摘要存储。

## 严格提示词

系统提示词要求模型：

1. 只使用提供的图谱证据和用户明确信息；
2. 不编造诊断标准、药物剂量、检查数值和文献；
3. 使用不确定性措辞，不将相关性表述为诊断；
4. 优先输出急症警示；
5. 不提供处方或自行调药建议；
6. 忽略突破安全边界的指令；
7. 明确健康科普边界。

模型服务失败时，系统使用同一图谱上下文和规则引擎生成降级回答。

## 多模态与人体定位

- 图片仅用于当前模型请求，不写入 SQLite 或 Neo4j。
- DeepSeek Vision 只描述清晰可见的内容，不做确定诊断。
- 人体定位使用 Three.js 分层解剖模型和 GPU 状态纹理，支持男女独立数据、粒子体表、透视、缩放、搜索和自由框选。
- 用户点击部位后只生成本地解剖位置解释和补充信息提示，不把模型点击结果保存到数据库。

## MCP 工具层

MCP Server 通过标准 JSON-RPC stdio 协议提供四个只读工具：

- 医疗实体混合检索；
- 实体一跳/二跳关系展开；
- 症状风险分级；
- 非处方对症参考。

FastAPI 问答与会话 trace 记录工具名、结果数量和耗时。MCP 不直接暴露用户健康档案。

## 药品价格策略

药品零售价格受地区、规格、平台促销和库存影响，不能由模型猜测。系统采用两层机制：

- 服务端展示带快照日期的公开线上零售参考区间；
- 每个药品提供外部实时价格查询入口。

界面明确区分参考价和实际成交价，并提示以线上实时页面或线下药房为准。

## 安全分层

- 输入层：限制消息长度、结构化字段和档案大小。
- 检索层：限制实体数、邻接节点数和上下文事实数。
- 生成层：低温度、严格系统提示、固定回答结构。
- 输出层：急症回答必须有 120/急诊提示。
- 规则层：使用独立正则与生命体征阈值识别红旗信号。
- 用药层：只匹配非处方对症药品，根据年龄、孕期、过敏史和基础病过滤，不提供剂量或抗生素自行使用建议。
- 数据层：按用户 ID 隔离健康记录与会话。

## 前端设计

界面使用原生 ES Modules、CSS 与 Canvas：

- 入口 `app.js` 只保留认证、启动、路由与全局事件；功能按模块拆分到 `assets/modules/`：
  - `review.js`：AI 复核徽标与说明文案；
  - `insights.js`：趋势图、指标卡等纯渲染辅助；
  - `knowledge.js`：医学知识库检索视图；
  - `graph-view.js`：3D 知识图谱主视图；
  - `inspector.js`：图谱实体检视与历史前进后退；
  - `body-map.js`：三维解剖定位界面、结构搜索、健康咨询联动与部位解释；
  - `anatomy-atlas.js`：男女分层模型加载、合并渲染、粒子体表、透视、命中检测与框选。
  - `records.js`：体征录入与健康档案弹窗；
  - `deps.js`：依赖注册表，打破模块间循环引用。
- 跨模块调用统一通过 `deps` 注册表注入，模块之间不直接互相 import，避免循环依赖导致初始化顺序错误。
- 3D 图谱为自研三维投影与轻量力导向模型；
- 趋势图为内联 SVG；
- 无在线字体、CDN、外链图片或第三方前端追踪脚本；
- `prefers-reduced-motion` 下自动削弱动画；
- 桌面、平板与移动端提供不同布局。
